# 非同期処理

---

## 同期処理と非同期処理

### 同期処理

- 1つのタスクを開始したら、そのタスクが完了してから次のタスクを開始する処理
- 前のタスクが完了しない限り次のタスクは実行されない
- アプリケーションの効率が下がる場合がある

### 非同期処理

- 1つのタスクを開始したら、そのタスクの完了を待たずに次のタスクを開始する処理
- 複数のタスクを並行で処理する
- アプリケーションの効率と応答性が向上する

## Pythonにおける非同期処理

### asyncioライブラリ

- イベントループの仕組みで複数の処理を同時に実行する
- スレッドを増やさずに並行処理ができるため軽量
- CPUの待ち時間を遊ばせないようにする仕組み

#### 処理イメージ

以下の繰り返し

1. タスクキューにやることリスト（実行待ちのコルーチン）が積まれる
2. イベントループはそこから1つ取り出してコルーチンを実行し始める
3. コルーチンが `await` に到達すると、処理完了までをOSに投げる
4. イベントループは次のタスクを取り出して実行し始める
5. OS側から完了通知が来たら、待ってたコルーチンがキューに戻る

#### async

- 関数を非同期にするための宣言

#### await

- 非同期関数の実行を待つための宣言
- このキーワード後の操作が完了するまでプログラムの実行を一時停止する

#### コルーチン（Coroutine）

- プログラムの実行を途中で一時停止し、後で続きから再開できる関数
- `async def` で定義され、`await` で非同期処理の完了を待つことができる
- FastAPIでは `async def` で定義されたエンドポイントは非同期コルーチンとして動作する

#### 注意点

ブロッキング処理問題
- `await` のない重い計算をコルーチンに入れるとイベントループが止まってしまう
- 対策として `loop.run_in_executor()` でスレッドプールに投げる

#### 呼び出し側と呼ばれる側の挙動パターン

| パターン | 呼び出し側 | 呼ばれる側 | 結果           |
| :------: | ---------- | ---------- | -------------- |
|    1     | async      | async      | 正常           |
|    2     | async      | sync       | 動くが注意     |
|    3     | sync       | async      | 典型的なバグ   |
|    4     | sync       | sync       | 通常の同期処理 |

1. 正常な非同期処理のパターン
   1. 呼ばれる側が I/O 待ちの間、ループが別タスクを実行し、完了後に再開する
   2. `await` を書き忘れるとパターン2のように同期的に呼んでしまうことになるので注意
2. 動くが注意が必要なパターン
   1. 呼ばれる側がCPUを占有し、処理が重いと他タスクをブロックする
   2. ファイルIOや `time.sleep` などのブロッキング処理を含む場合、イベントループ全体が止まる
   3. 軽い計算だけの関数なら問題ないが、I/Oを伴うなら `run_in_executor` に逃がす
3. 典型的なバグのパターン
   1. コルーチンオブジェクトが返るだけで関数の中身は実行されない
   2. エラーも出ない
4. 通常の同期処理のパターン
   1. I/O 待ち中はスレッド全体がブロックされる

## FastAPIでの非同期処理

### httpxライブラリ

 - HTTPリクエストを送るための非同期対応ライブラリ
 - `async` / `await` 構文を使用して非同期のHTTPリクエストを行う
